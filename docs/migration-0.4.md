# Migrating to 0.4

This guide is for applications built on iec61850-rust 0.3.x. Every crate of
the workspace moves to 0.4.0 together, and a dependency on one of them should
be raised with the others. `iec61850-scl-build` and `iec61850-scl` must be the
same version, so a build script and the run-time crate are upgraded in one
step, and a `model.rs` generated by an older `iec61850-scl-build` must be
regenerated.

Each section below is a use case. Within it, each change gives the reason, the
0.3 form, the 0.4 form and, where the bytes on the wire change, what a peer
sees. [CHANGELOG.md](../CHANGELOG.md) lists every change.

## Upgrade order

Most changes are local to one side of an association: upgrading the server, or
the client, is enough. The table lists the changes a peer can see and which
side has to move; the On the wire section of
[CHANGELOG.md](../CHANGELOG.md) describes each in full.

| Change | What a peer sees | Upgrade |
|---|---|---|
| GOOSE control block layout (IEC 61850-8-1 Table 83) | The GoCB structure starts with `GoEna` and ends with `FixedOffs`; `GoCBRef` is no longer a component | **Client and server together**: neither version decodes the other's GoCB |
| Association release | After the Conclude response the server waits for the client's FINISH carrying the RLRQ and answers with the RLRE in a DISCONNECT; it sends no FINISH of its own | Server. A client that waits for a FINISH from the server must send its own first; the `iec61850-mms` client has done so since 0.3.3 |
| Refused association | A Session REFUSE carrying a Presentation CPR instead of an accepted session with a rejected AARE | Server; a client reports `ClientError::SessionRefused` |
| Peer release answered by the client | A Session DISCONNECT carrying an RLRE in answer to the peer's FINISH | Client only |
| Proposed outstanding requests | The Initiate request carries the configured `max_outstanding` | Client only |
| Data object member order from SCL | Members follow the DOType declaration order | Server; a client must fetch the type again instead of reusing a structure read from 0.3 |
| SCL `count` | The attribute or sub-data-object is an MMS array | Server |
| Report control block instance names | `register_from_model` names indexed instances `<name>01` … | Server; clients address the new names |
| `DatSet` values | `<LD>/<LN>$<name>` for URCBs, BRCBs, LCBs, GoCBs and reports; the published GOOSE carries the qualified GoCB data set reference | Server; a client writing back what it read needs no change |
| GoCB `MinTime` and `MaxTime` | The publisher's T1 and Tmax, 4 and 1000 ms by default, instead of 0 | Server |
| Presentation contexts in the CPA | Each proposed context is answered in order; a context other than ACSE and MMS with BER is provider-rejected | Server |
| Unchanged values | No data-change report or log entry for a rewrite of the same value | Server only |
| Report segmentation | Segments sized to the negotiated maximum PDU size, each marking only its own members | Server; a client must read every segment |
| URCB reservation | Enabling reserves; disabling keeps the reservation; `Resv` is not writable while enabled | Server |
| URCB configuration | An unreserved URCB accepts writes of its other attributes from any client without reserving it, so one request may configure it and end with `RptEna = TRUE` | Server only |
| `GI` while disabled | `GI = TRUE` to a control block whose `RptEna` is FALSE answers `temporarily-unavailable`, and `GI` reads FALSE | Server; a client writes `GI` after `RptEna` |
| `Owner` and `ResvTms` from SCL | Present only when the file declares `<ReportSettings owner="true" resvTms="true">` | Server |
| SCL `<TrgOps>` without `gi` | The report control block's `TrgOps` includes GI | Server |
| BRCB `ConfRev` | Counts `DatSet` changes only | Server only |
| Journal names | A journal is named only by the `LogRef` of its log control block | Server; a client that used the control block path uses the LogRef |
| ReadJournal fields | Every combination of the optional fields is served | Server; a 0.3 server refuses the new combinations from a 0.4 client |
| Setting group values | SelectActiveSG and SelectEditSG load the group's values | Server only |
| GoCB `GoID` and `DatSet` under `Edition::Ed2_1` | Writes answer `object-access-denied` | Server configuration |
| Select of a selected object | Refused whichever client sends it | Server |
| Operate with `operTm` other than 0 | Refused with the add cause Not-supported | Server |
| Cancel of an idle direct-control object | Refused with Not-supported | Server |
| Select timeout | A timer ends the selection when `sboTimeout` elapses, without waiting for the next request | Server |
| Control settings | `ctlModel`, `sboTimeout`, `sboClass` and `operTimeout` come from the model's attributes where it declares them | Server |
| 802.1Q tag on GOOSE and Sampled Values | Frames carry `81 00 80 00` after the source address | Publisher only; receivers must accept tagged frames |
| Data access results | Range and length checks on writes, `temporarily-unavailable` for SE outside an edit session, `definition object-undefined` for an unknown CreateDataSet member | Server only |
| Request size limits | CreateDataSet takes up to 1024 members and a Write up to 4096 items; beyond, `resource capability-unavailable` instead of `access other` at 100 | Server only |
| BRCB `BufOvfl` | The first report after every enable carries `BufOvfl` TRUE (IEC 61850-7-2 §17.2.3.2.2.8), whatever the client resynchronized on | Server |
| Array element data set members | GetDataSetDirectory lists such a member as the variable naming the array with an alternate access of the index and its components (IEC 61850-8-1 §24.2.2.4.1.3); SetDataSetValues writes it as the element; CreateDataSet takes it in the same form | Server; a 0.3 server refuses the element member a 0.4 client sends |
| TLS refusal | A refused client reads the alert instead of a reset | Server (the acceptor); a client of any version benefits |
| GOOSE destination from SCL `<GSE>` | A GoCB registered by `register_from_model` publishes to the APPID, destination MAC and VLAN of its `<GSE>`, every `MinTime` to `MaxTime`, and a client reads them in `DstAddress`, `MinTime` and `MaxTime` | Server |
| GoCB without a destination | In an SCL whose Communication section connects the IED, a GoCB without `<GSE>`, or whose `<GSE>` has no `MAC-Address`, reads `DstAddress` `Addr` as `00-00-00-00-00-00`, and `GoEna = TRUE` answers `temporarily-unavailable` (IEC 61850-8-1 §25.3.2) | Server |
| GOOSE `t` from the model | A publisher registered by `register_from_model` sends the time of the last stNum change, with the server's `time_quality`, instead of a NULL `t` | Server |
| GOOSE `t` and Sampled Values `refrTm` with TimeAccuracy 25 to 30 | The frame is dropped as malformed (IEC 61850-8-1 Table 36) | Receiver only; publishers of this crate cannot send such a value |
| Refused authentication | With an `AssociationAuthenticator` installed, a refused AARQ gets a Session REFUSE carrying a CPR whose AARE is rejected-permanent with the authenticator's diagnostic and carries an Initiate-ErrorPDU access object-access-denied | Server; a 0.4 client reports `ClientError::AuthenticationRejected` |
| SE write outlasting its edit session | `temporarily-unavailable`, and nothing stored, when the edit session expires, is cancelled or is opened again while the write handler runs | Server only |
| Write access policy changed while running | The next Write of every association follows the new policy | Server only |
| PurgeBuf | Events still inside `BufTm` are discarded with the buffer and never reported | Server only |
| `GI` written by `set_rcb_values` | The value the `RcbHandle` holds, `GI = FALSE` unless `set_gi(true)` was called, instead of always `GI = TRUE` | Client only |
| Connecting while connected | The previous server sees its connection close without a release | Client only |
| Dropped client calls | A call dropped while its request is being written closes the connection | Client only |

## Every crate

The public error, outcome, configuration, context, parameter, state, report,
control block and model node types of every crate are `#[non_exhaustive]`, so
that later releases can add a variant or a field without breaking callers.
Value enums fixed by the standard (`FC`, `MmsValue`, `Dbpos`, `ControlModel`,
`OrCat`) and the protocol structures callers build field by field (`TrgOps`,
`Quality`, and the MMS PDU structs other than `ServiceError`,
`IdentifyResponse`, `StatusResponse`, `ReadJournalRequest`, `WireJournalEntry`
and `WireJournalVariable`) are unchanged. Each struct variant of an error or
event enum is `#[non_exhaustive]` as well, so a field can be added to it later.

### Matching an affected enum

A `match` outside the defining crate needs a wildcard arm.

In 0.3:

```rust
match outcome {
    ControlOutcome::Success => {}
    ControlOutcome::Failure(cause) => {}
}
```

In 0.4:

```rust
match outcome {
    ControlOutcome::Success => {}
    ControlOutcome::Failure { add_cause, .. } => {}
    _ => {}
}
```

### Error and event variants

Every struct variant of a public error or event enum, across all crates, is
`#[non_exhaustive]`: for example `ClientError::Timeout` and
`ClientError::NameListLimit` in `iec61850-client`, `ClientError::ServiceError`
in `iec61850-mms`, `GooseEvent::NewState` and `SntpClockStatus::Synchronized`.
Outside its crate such a variant cannot be built with a struct expression, and
a pattern on it ends with `..`; a test compares with `matches!` instead of
`assert_eq!`. Value variants, which callers build to describe data, names,
types and PDUs (`MmsValue`, `MmsData`, `ObjectName`, `TypeSpecification`,
`MmsTypeSpec`, `MmsLeafType`, `AlternateAccessSelector`, `CotpPdu`), stay
constructible and can be matched exhaustively.

In 0.3:

```rust
Err(ClientError::Timeout { after_ms }) => {}
assert_eq!(e, ClientError::NameListLimit { limit: 3_000 });
let e = iec61850_mms::ClientError::ServiceTimeout { timeout_ms: 300 };
```

In 0.4:

```rust
match result {
    Err(ClientError::Timeout { after_ms, .. }) => println!("timed out after {after_ms} ms"),
    _ => {}
}
assert!(matches!(e, ClientError::NameListLimit { limit: 3_000, .. }));
let mms_error = iec61850_mms::ClientError::service_timeout(300);
```

The constructors for the variants a caller has to build are listed under
[Service errors](#service-errors) and [SNTP](#sntp).

### Building an affected struct

A struct literal no longer compiles, and neither does the
`..Default::default()` form. Start from `Default`, a constructor or a builder,
and assign the public fields.

In 0.3:

```rust
let config = IedServerConfig {
    max_mms_connections: 4,
    ..Default::default()
};
let ln = LogicalNode {
    prefix: String::new(),
    class: "GGIO".into(),
    inst: "1".into(),
    dos,
    datasets: vec![],
    rcbs: vec![],
    gocbs: vec![],
    svcbs: vec![],
    lcbs: vec![],
    sgcb: None,
};
```

In 0.4:

```rust
let mut config = IedServerConfig::default();
config.max_mms_connections = 4;
let ln = LogicalNode::new("", "GGIO", "1", dos);
```

A handle that shares the value lock of a served attribute is built with
`DataAttribute::with_shared_value`:

```rust
let handle = DataAttribute::with_shared_value(
    da.name.clone(), da.fc, da.ty, da.trg_ops, Arc::clone(&da.value),
);
```

A pattern that destructures an affected struct needs a trailing `..`.

The constructors added for this are `LogicalDevice::new`, `LogicalNode::new`,
`DataObject::new`, `DataAttribute::with_shared_value`, `DataSet::new`,
`DataSetEntry::new`, `ReportControlBlock::new`, `GooseControlBlock::new`,
`SvControlBlock::new` and `LogControlBlock::new` in `iec61850-model`;
`ServiceError::with_additional_code` and
`ServiceError::with_additional_description` in `iec61850-mms`;
`GoosePdu::new` and `GooseFrameHeader::new` in `iec61850-goose`; `Asdu::new`,
`SavPdu::new` and `SvFrameHeader::new` in `iec61850-sv`; `IecObjectPath::new`,
`IecObjectPath::with_array` and `ArrayElement::new` in `iec61850-client`;
`ControlObjectConfig::new`, `ReadContext::new`, `WriteContext::new`,
`ReportEncodeParams::new`, `BrcbReportEncodeParams::new`, `JournalEntry::new`
and `JournalEntryData::new` in `iec61850-server`. Each documents the value it
gives the fields it does not take.

Nothing changes on the wire.

## Client applications

### Errors carry their cause

`ClientError` reports an MMS layer failure on a typed variant instead of the
text in `ClientError::Mms`, so a caller can tell a timeout from a refusal
without parsing a message.

| Cause | Variant |
|---|---|
| Request timeout | `Timeout { after_ms, .. }` |
| Connect timeout, for the TCP connection or the COTP exchange | `ConnectTimeout { after_ms, .. }` |
| TLS handshake failed | `TlsHandshake { kind, message, .. }` |
| Peer closed the transport, sent a COTP DR or aborted | `ConnectionLost` |
| Peer released the association | `ReleasedByPeer` |
| Transport failure, such as a refused TCP connection or a TLS alert on an established association | `Transport(TransportError)` |
| Confirmed-ErrorPDU | `Service { error_class, service_specific, .. }` |
| RejectPDU | `Reject { reason, .. }` |
| Conclude refused | `ConcludeRejected` |
| ACSE association refused | `AssociateFailed` |
| Initiate-ErrorPDU | `InitiateFailed { error_code, .. }` |
| Request above the negotiated PDU size | `PduTooLarge { pdu_size, max_size, .. }` |
| Outstanding request limit held by timed-out requests | `OutstandingCallLimit` |
| GetNameList walk past the name limit | `NameListLimit { limit, .. }` |
| GetNameList walk the server does not move on | `NameListNotAdvancing` |
| Journal read by `query_journal_all` the server does not move on | `JournalNotAdvancing` |
| No command termination within the wait | `CommandTerminationTimeout { after_ms, .. }` |
| Association not established at the MMS layer | `NotConnected` |

`Mms(String)` remains for failures with no variant of their own. A variant
that replaces a `ClientError::Mms` text for an MMS layer cause renders that
same text, so log lines keep reading the same, with these exceptions:
`NotConnected` renders `connection is not established`, `Transport` renders
`mms layer error: transport error: …` for failures that used to be reported
as a lost connection or an ISO error, `TlsHandshake` renders
`mms layer error: TLS handshake failed: …`, and `NameListLimit`,
`NameListNotAdvancing`, `JournalNotAdvancing` and
`CommandTerminationTimeout` have texts of their own.

In 0.3:

```rust
match result {
    Err(ClientError::Mms(s)) if s.contains("timed out") => retry(),
    Err(ClientError::Mms(s)) if s.contains("connection was lost") => reconnect(),
    _ => {}
}
```

In 0.4:

```rust
match result {
    Err(ClientError::Timeout { .. }) => retry(),
    Err(ClientError::ConnectionLost
        | ClientError::ReleasedByPeer
        | ClientError::Transport(_)) => reconnect(),
    Err(ClientError::Service { error_class, .. }) => {
        let (class, code) = (error_class.context_tag(), error_class.code());
        println!("refused: class {class}, code {code}");
    }
    Err(ClientError::Reject { reason, .. }) => {
        println!("rejected: type {}", reason.reject_type());
    }
    _ => {}
}
```

A caller that treated `ConnectionLost` as the end of the connection handles
`Transport(_)` and `ReleasedByPeer` the same way. The struct variants cannot be
built outside the crate, and a pattern on one ends with `..` (see
[Every crate](#every-crate)).

A refused service carries the serviceSpecificInformation of its ServiceError
as `service_specific`; a refused DeleteDataSet reports how many data sets the
server deleted:

```rust
if let Err(ClientError::Service {
    service_specific: Some(ServiceSpecificInfo::DeleteNamedVariableList(n)),
    ..
}) = result
{
    println!("the server deleted {n} data sets");
}
```

### TLS handshake failures and the connect deadline

A failed TLS handshake in `connect_tls` returns `ClientError::TlsHandshake`,
whose `kind` is a `TlsFailureKind`: the peer certificate was rejected
(`Verification`), the peer sent a fatal alert (`AlertReceived`), no TLS
version or cipher suite in common (`VersionUnsupported`, `CipherUnsupported`),
the deadline ran out (`Timeout`), the transport broke (`Io`), or another TLS
error (`Other`). It used to be the text of `ClientError::Mms`.
`TlsFailureKind` is defined with or without the `tls` feature; it is
non-exhaustive, so a `match` on it needs a wildcard arm, and a pattern on
`TlsHandshake` ends with `..`.

A TLS error after the handshake, until the MMS Initiate response is
accepted, is a `TlsHandshake` too. This is how a TLS 1.3 server refuses a
missing or rejected client certificate: the client completes its side of the
handshake and reads the fatal alert during the COTP exchange, which returns
`TlsHandshake` with `TlsFailureKind::AlertReceived` and the alert named in
`message`, for example `received fatal alert: CertificateRequired`. A TLS
alert on an established association is `ClientError::Transport`, and so is
a transport failure with no TLS error behind it.

One deadline of `connect_timeout_ms` now bounds the TCP connection, the TLS
handshake of `connect_tls` and the COTP connection request and confirm
together. The COTP exchange had no timeout before, so a peer that accepted
the TCP connection and never answered held the client indefinitely. Running
out of the deadline during the handshake returns `TlsHandshake` with
`TlsFailureKind::Timeout`; during the TCP connection or the COTP exchange it
returns `ConnectTimeout`. `connect_via`, which starts from a connected
transport, bounds its COTP exchange by the same setting. The Session, ACSE and
MMS Initiate exchange that follows is still bounded by `request_timeout_ms`.

In 0.3:

```rust
match conn.connect_tls(addr, &connector, name).await {
    Err(ClientError::Mms(text)) if text.contains("TLS handshake") => {}
    _ => {}
}
```

In 0.4:

```rust
match result {
    Err(ClientError::TlsHandshake { kind: TlsFailureKind::Verification, .. }) => {
        println!("untrusted certificate")
    }
    Err(ClientError::TlsHandshake { kind: TlsFailureKind::AlertReceived, message, .. }) => {
        println!("refused by the server: {message}")
    }
    Err(ClientError::TlsHandshake { kind, message, .. }) => println!("TLS handshake ({kind}): {message}"),
    Err(ClientError::ConnectTimeout { after_ms, .. }) => println!("no connection within {after_ms} ms"),
    _ => {}
}
```

Nothing changes on the wire.

### Failed control commands carry their LastApplError

IEC 61850-8-1 §20 has the server report a refused command with a
LastApplError, and a negative CommandTermination carries one. 0.4 returns it
with the outcome instead of through a separate call, and
`ControlObjectClient::last_appl_error()` is removed.

In 0.3:

```rust
match spc.operate(v).await? {
    ControlOutcome::Failure(cause) => {
        let detail = spc.last_appl_error();
    }
    _ => {}
}
```

In 0.4:

```rust
match spc.operate(v).await? {
    ControlOutcome::Failure { add_cause, last_appl_error, .. } => {
        println!("refused: {add_cause:?}, {last_appl_error:?}");
    }
    _ => {}
}
```

or, without a `match`:

```rust
let outcome = spc.operate(v).await?;
if let Some(e) = outcome.last_appl_error() {
    println!("{} {:?} ctlNum {} {:?}", e.ctl_obj, e.error, e.ctl_num, e.add_cause);
}
```

A normal-security server may refuse without a LastApplError (IEC 61850-8-1
§20.7.5, §20.8.5); `last_appl_error` is then `None` and `add_cause` is
`Unknown`.

`select()` returns a `ControlOutcome` instead of a `bool`, so a denied
selection carries its cause.

In 0.3:

```rust
if spc.select().await? {
    // selected
} else {
    let cause = spc.last_appl_error();
}
```

In 0.4:

```rust
let outcome = spc.select().await?;
if outcome.is_success() {
    // selected
} else {
    let cause = outcome.add_cause();
}
```

An enhanced-security Operate whose CommandTermination does not arrive within
the wait, and a `wait_command_termination` call that times out, return
`ClientError::CommandTerminationTimeout { after_ms }` instead of
`ClientError::Mms`.

A test double builds outcomes with `ControlOutcome::failure` and
`LastApplError::new`:

```rust
let outcome = ControlOutcome::failure(Some(LastApplError::new(
    "LD/GGIO1$CO$SPCSO1$Oper", ControlLastApplError::NoError,
    OriginValue::bay_control(), 1, ControlAddCause::BlockedByInterlocking,
)));
let bare = ControlOutcome::failure(None); // Unknown, no LastApplError
```

### AddCause and LastApplError names

`ControlAddCause` and `ControlLastApplError` use the names of IEC 61850-8-1
§20.11, in the client and the server crate alike. The values on the wire are
unchanged.

| 0.3 | 0.4 |
|---|---|
| `ControlAddCause::BlockedBySynchroCheck` | `ControlAddCause::BlockedBySynchrocheck` |
| `ControlAddCause::AbortionByCommand` (24) | `ControlAddCause::BlockedByCommand` |
| `ControlLastApplError::TimeoutTest` | `ControlLastApplError::TimeoutTestNotOk` |
| `ControlLastApplError::OperationFailed` | `ControlLastApplError::OperatorTestNotOk` |

### Reports

`ClientReport::included` holds one flag per data set member, set when the
latest report, or the latest segment of a segmented one, carried the member.
`data_set_values` keeps the previous value of an omitted member, so read the
flag instead of inferring inclusion from `reasons`:

```rust
let fresh = report.included[i];
```

A segmented report is delivered one segment at a time: the callback runs once
per segment, and `included`, `reasons` and `segmentation` describe that
segment. The client does not reassemble segments. A 0.4 server sizes segments
to the PDU size the association negotiated, so a client that proposes a small
size receives more segments than before, and a general interrogation that
used to arrive in one callback may arrive in several.

Against a 0.4 server, a report control block behaves as IEC 61850-7-2 and
IEC 61850-8-1 Tables 72 and 73 define:

- `DatSet` reads back as `<LD>/<LN>$<name>`, also in the data-set-name field of
  a report. A client that compares it with the LN-relative name compares with
  the qualified one; one that writes back the value it read needs no change.
- Writing `RptEna = TRUE` to an unreserved URCB reserves it for the writer.
  Writing `RptEna = FALSE` keeps the reservation; write `Resv = FALSE` as well
  to free the URCB for another client.
- The other writable attributes of an unreserved URCB accept writes from any
  client without reserving it, so one request may set `TrgOps`, `IntgPd` and
  the rest and end with `RptEna = TRUE`. A client that inferred the
  reservation from the refusal of such a write reads `Resv` instead.
- `GI = TRUE` while `RptEna` is FALSE is refused with
  `temporarily-unavailable` and leaves `GI` FALSE (IEC 61850-7-2
  §17.2.2.13); write `GI` after `RptEna = TRUE`, in the same request or a
  later one. `IedConnection::set_rcb_values` already writes it last.
- `Resv` of an enabled URCB and `ResvTms` of an enabled BRCB are refused with
  `temporarily-unavailable`; write `RptEna = FALSE` first.
- `EntryID` and `PurgeBuf` of an enabled BRCB are refused with
  `temporarily-unavailable`; `IedConnection::set_rcb_values` already writes
  `RptEna = FALSE` first when `RPT_ENA` is in the mask.
- A BRCB's `ConfRev` counts `DatSet` changes only.
- `Owner` names the client holding the control block. It is optional, and so
  is a BRCB's `ResvTms`: a control block built from an SCL file has them only
  when the file declares them, and a Read or Write of a missing one answers
  `object-non-existent`. A client reads `Owner` as optional, and reserves a
  BRCB without `ResvTms` by enabling it.

The client checks a report against the data set its kept values came with.
A report whose DatSet or ConfRev differs from that data set discards the kept
values and data references and takes its own data set size, so a member it
omits reads as `None` instead of the value of the previous data set; a
report that carries neither is held to the previous data set. A report the
client rejects, for instance for an over-long data set name or too few
values, leaves the subscription as it was.

### GI writes

`IedConnection::set_rcb_values` writes the GI value the `RcbHandle` holds
when the mask names `GI`; 0.3 wrote `GI = TRUE` whatever the handle held.
Set it before the write.

In 0.3:

```rust
conn.set_rcb_values(&rcb, RcbWriteMask::GI, false).await?;
```

In 0.4:

```rust
rcb.set_gi(true);
conn.set_rcb_values(&rcb, RcbWriteMask::GI, false).await?;
```

A handle whose GI was never set writes `GI = FALSE`, which a 0.4 server
accepts while the control block is disabled and which starts no general
interrogation (IEC 61850-7-2 §17.2.2.13). `IedConnection::trigger_grefcb`
still writes `GI = TRUE`. Only the client changes.

### Journals

`JournalQuery` is a struct of the four ReadJournal selections, with a builder
method for each; `by_time` and `after_entry` still build QueryLogByTime and
QueryLogAfter. `query_journal` sends one request for any query,
`JournalQuery::continuation` gives the request that continues a page, and
`query_journal_all` follows `moreFollows` to the end of the selection. A
continuation keeps the end time, which `query_journal_after_entry` did not.
`query_journal_all` returns each selected entry once, none past the end time
and no more than the entry count, also from a server that resends the entry
a continuation resumes after or ignores the end time or the entry count. A
read that brings no new entry while the server reports more fails with
`ClientError::JournalNotAdvancing`. A single `query_journal` returns the
page as the server sent it.
`QueryJournalNotImplemented` is removed; nothing returned it, so a `use` of it
is deleted.

In 0.3:

```rust
match query {
    JournalQuery::TimeRange { start_ms, end_ms } => {}
    JournalQuery::StartAfter { .. } => {}
}
let (page, more) = conn.query_journal_by_time(log_ref, start, end).await?;
// then: conn.query_journal_after_entry(log_ref, last.time_ms, last.entry_id)
```

In 0.4:

```rust
let query = JournalQuery::by_time(start, end);
let all = conn.query_journal_all(log_ref, &query).await?;
// or page by page:
let (page, more) = conn.query_journal(log_ref, &query).await?;
let next = query.continuation(&page);
```

A 0.4 server names a journal only by the `LogRef` of its log control block, as
GetNameList lists it. A client that read a journal through the control block
path reads it through the LogRef, which is readable as `<LCB>$LogRef` (FC LG):

```rust
// 0.3: conn.query_journal_by_time("IED1LD0/MMXU1$LG$lcb01", start, end)
let (page, more) = conn.query_journal_by_time("IED1LD0/MMXU1$GeneralLog", start, end).await?;
```

### GOOSE control block values

The GoCB is the MMS structure of IEC 61850-8-1 §18.1.1.1.1 Table 83, and the
reference is the variable name rather than a component, so
`GoCBValues::go_cb_ref` is removed. `min_time_ms` and `max_time_ms` are
`Option<u32>`, and `fixed_offs` is new. `GoCBValuesWrite` can write `DatSet`.

In 0.3:

```rust
let values = conn.get_gocb_values(gocb_ref).await?;
let reference = values.go_cb_ref;
let min_time = values.min_time_ms;
```

In 0.4:

```rust
let values = conn.get_gocb_values(gocb_ref).await?;
let reference = gocb_ref; // the reference passed in
let min_time = values.min_time_ms.unwrap_or_default();
conn.set_gocb_values(gocb_ref, GoCBValuesWrite::new().with_dat_set("LD0/LLN0$ds2")).await?;
```

A 0.3 client cannot decode the GoCB of a 0.4 server, nor the reverse: upgrade
both together. Under `Edition::Ed2_1` the server refuses writes of `GoID` and
`DatSet` with `object-access-denied`.

### Refused associations

A 0.4 server refuses an association with a Session REFUSE carrying a
Presentation CPR, which the client reports as `ClientError::SessionRefused`
where it used to report `AssociateFailed` or `InitiateFailed`:

```rust
match conn.connect("192.0.2.10", 102).await {
    Err(ClientError::SessionRefused { reason_code: Some(2), .. })
    | Err(ClientError::AssociateFailed) => println!("refused"),
    _ => {}
}
```

### ACSE credentials and refused authentication

`IsoConnectionParameters::authentication` holds the ACSE credentials the
client writes into its AARQ, `AcseAuth::None` by default. `AcseAuth::Password`
sends the password mechanism with a charstring value; the password travels in
clear unless the association runs over TLS. A peer that refuses the
association with an AARE whose diagnostic names the calling AP-title,
AE-qualifier or invocation identifier, or the authentication, is reported as
`ClientError::AuthenticationRejected`, whether the AARE arrives in a Session
ACCEPT or inside the CPR of a Session REFUSE. A refusal without such a
diagnostic is reported as before. `AcseAuth::other(mechanism, value)` sends
any other mechanism, written as given: the content octets of its
mechanism-name OBJECT IDENTIFIER and the complete Authentication-value
encoding.

In 0.3:

```rust
Err(ClientError::AssociateFailed) => {}
```

In 0.4:

```rust
let mut params = IsoConnectionParameters::default();
params.authentication = AcseAuth::Password(b"secret".to_vec());
let conn = IedConnection::with_iso_parameters(params);
match conn.connect("192.0.2.10", 102).await {
    Err(ClientError::AuthenticationRejected { diagnostic, .. }) => println!("refused: {diagnostic}"),
    _ => {}
}
```

An `AcseAuthenticator` of `iec61850-mms` receives an AARQ that names another
mechanism, or a password value that is not a charstring, as `AcseAuth::Other`
with the mechanism-name and the value; 0.3 presented it as `AcseAuth::None`.
An authenticator that accepted `None` decides on `Other` as well, and a
`match` on `AcseAuth` needs a wildcard arm. The AARQ on the wire is the same.

In 0.3:

```rust
match auth {
    AcseAuth::None => true,
    AcseAuth::Password(p) => p.as_slice() == b"secret",
    AcseAuth::TlsCertificate(_) => false,
}
```

In 0.4:

```rust
struct Gate;
impl AcseAuthenticator for Gate {
    fn authenticate(&self, auth: &AcseAuth, _app_ref: &IsoApplicationReference) -> bool {
        match auth {
            AcseAuth::Password(p) => p.as_slice() == b"secret",
            AcseAuth::Other { .. } => false, // or inspect mechanism and value
            _ => false,
        }
    }
}
```

A server built on `IedServer` decides through an `AssociationAuthenticator`;
see [Gating associations](#gating-associations).

### Directory walks

A GetNameList walk that passes the name limit fails with
`ClientError::NameListLimit { limit }` instead of `ClientError::Mms`. The limit
is set per connection:

```rust
let conn = IedConnection::new().with_max_name_list_names(50_000);
```

A walk the server does not move on, because a page that reports more names
ends on its continuation, brings no name not yet received or is empty, fails
with `ClientError::NameListNotAdvancing` instead of `ClientError::Mms`; an
empty page used to end the walk with the names received so far. The walk
keeps each name once, in the order the server sends it, and requires no
order. Nothing changes on the wire.

In 0.3:

```rust
match conn.get_server_directory(false).await {
    Err(ClientError::Mms(msg)) if msg.contains("does not advance") => {}
    _ => {}
}
```

In 0.4:

```rust
match conn.get_server_directory(false).await {
    Err(ClientError::NameListNotAdvancing) => println!("the server repeats its pages"),
    Err(ClientError::NameListLimit { limit, .. }) => println!("more than {limit} names"),
    _ => {}
}
```

The device model the directory services cache belongs to the association it
was read on. After a new association, also one to another server,
`IedConnection::cached_device_model()` returns `None` until a directory call
reads the model again.

### Results that change against a 0.4 server

- A write of a whole data object (FCD) is served instead of answering
  `object-access-unsupported`.
- A write of an integer outside its declared width answers
  `object-value-invalid`, and a string, octet string or binary time of a wrong
  length `type-inconsistent` (IEC 61850-8-1 §8.1.1 Table 15, §8.1.3.4.4.2).
- A Quality written with fewer bits reads back with 13.
- A read of FC SE before SelectEditSG answers `temporarily-unavailable`, and a
  write of FC SE outside the caller's edit session answers
  `temporarily-unavailable` where it used to answer `object-access-denied`.
  Treat both as "no edit session". So does a write of FC SE whose edit
  session expires, is cancelled or is opened again while the server's write
  handler runs; nothing of it is stored.
- A CreateDataSet member naming an object that does not exist answers
  `definition object-undefined` instead of `access object-non-existent` or
  `definition invalid-address`. A data object, a sub-data-object or a
  constructed attribute is accepted as a member, and its value is a structure.
  A member naming an array element, such as `LD/MHAI1.HA.phsAHar(3).cVal.mag.f`,
  is sent as the array name with an alternate access and accepted.
- CreateDataSet takes up to 1024 members and a Write up to 4096 items, where
  both stopped at 100; beyond, the server answers
  `resource capability-unavailable` instead of `access other`.
- An attribute declared with `count` is an MMS array; an element is read and
  written by index, for example `LD/LN.DO.da(2)` through `read_object`.
- A data object read from an SCL-configured server lists its members in the
  DOType declaration order; fetch its type again rather than reusing one read
  from 0.3.

## Server applications

### Control handlers live on the registry entry

The setters on `ControlObject` (`set_check_handler`,
`set_wait_for_exec_handler`, `set_operate_handler`) and the fields they wrote
never had an effect: the control services call the handlers of
`ControlObjectEntry`. They are removed, together with
`ControlAction::set_add_cause` and `set_error`; a handler reports its outcome
through the `ControlAddCause` it returns.

In 0.3:

```rust
obj.set_operate_handler(handler); // had no effect
registry.register(ControlObjectEntry::new(obj));
```

In 0.4:

```rust
registry.register(ControlObjectEntry::new(obj).with_operate(handler));
```

A check refuses by returning its cause:

```rust
impl CheckHandler for Interlock {
    fn check(
        &self,
        _action: &ControlAction,
        _ctl_val: Option<&MmsValue>,
        _test: bool,
        _interlock_check: bool,
    ) -> Result<(), ControlAddCause> {
        Err(ControlAddCause::BlockedByInterlocking)
    }
}
```

### Control settings come from the model

A control object follows the `ctlModel`, `sboTimeout`, `sboClass` and
`operTimeout` attributes the model declares for its data object, read at each
request. `ControlObjectConfig` supplies the values the model does not declare,
and `ControlObject::set_oper_timeout_ms` is replaced by the
`oper_timeout_ms` field.

In 0.3:

```rust
obj.set_oper_timeout_ms(1_000);
```

In 0.4:

```rust
let mut config = ControlObjectConfig::new("Pos", "CSWI1", "IED1LD0", ControlModel::SboEnhanced);
config.oper_timeout_ms = 1_000;
let obj = ControlObject::new(config);
```

`ControlObjectsRegistry::register_from_model` registers every controllable data
object, and an application then attaches its handlers:

```rust
server.control_objects().register_from_model(&server.model());
if let Some(e) = server.control_objects().lookup("IED1LD0", "CSWI1", "Pos") {
    server.control_objects().register(e.with_operate(handler));
}
```

When the configuration and the model disagree, the model wins once the server
has served a request for the object. A value set in `ControlObjectConfig`,
such as `sbo_timeout_ms` or `oper_timeout_ms`, therefore has no effect for an
attribute the model declares, and code that overrode a setting this way
stops doing so without an error. To decide a setting in code, leave the
attribute out of the model or write its value, for example `sboTimeout`
through `update_*`.

### Other control API changes

- `ControlState::WaitForActivationTime` and `WaitForSelect`, which no
  transition entered, and `ControlAction::ctl_time_ms` are removed.
- `ControlAction::conn_id` returns the `ConnectionId` of the association that
  issued the request, or 0 when none did; a selection that ends by timeout or
  by the loss of its association reports the association that held it.
- `CommandTerminationSink::send_negative` takes the `Error` member of the
  LastApplError, and the `Negative` variants of `TerminationEvent` and
  `ConnectionTerminationEvent` carry it as `error`:

```rust
impl CommandTerminationSink for MySink {
    fn send_positive(&self, _obj_ref: &str, _conn_id: u64, _oper_value: Bytes) {}
    fn send_negative(
        &self,
        _obj_ref: &str,
        _conn_id: u64,
        _add_cause: ControlAddCause,
        _error: ControlLastApplError,
        _oper_value: Bytes,
    ) {
    }
}
```

- A `SelectStateChangedHandler` hears of every change of a selection, the
  select included (`is_selected` set, reason `Selected`), the end of an
  operate-once command (`OperateDone`) and an Operate whose refusal ends the
  selection (`OperateRefused`). A handler that treated every call as a
  deselection reads `is_selected` and `reason`:

```rust
impl SelectStateChangedHandler for MyHandler {
    fn on_select_state_changed(
        &self,
        _action: &ControlAction,
        is_selected: bool,
        reason: SelectStateChangedReason,
    ) {
        if is_selected {
            // selected: reason is Selected
        } else {
            println!("selection ended: {reason:?}");
        }
    }
}
```

- The server writes `stSeld` (IEC 61850-7-3) on every selection change,
  through the update path, before calling the handler. An application that
  wrote `stSeld` from its handler stops doing so.

On the wire: an Operate carrying an `operTm` other than 0 is refused with
Not-supported instead of being executed at once, a second Select of a selected
object is refused whichever client sends it, a Cancel of an idle
direct-control object is refused with Not-supported, and a selection ends on a
timer when `sboTimeout` elapses. A client that relied on re-selecting to
restart the timeout cancels first; one that sent an activation time sends
`operTm` 0.

### Registering what the model declares

`IedServer::register_from_model` registers, in one call, every data set, report
control block, GOOSE control block, log control block and controllable data
object the model declares; `register_from_model_with` takes
`FromModelOptions` for the log storage and the GOOSE destinations the model
does not hold. Nothing is registered unless the application calls it.

```rust
let summary = server.register_from_model()?;
println!("{} report control blocks", summary.urcbs + summary.brcbs);
```

A report control block is registered once per instance it declares
(IEC 61850-8-1 §17.1.2, §17.1.3): `<name>01` to `<name>NN` when `indexed`,
the SCL default, and `<name>` otherwise. An application that switches from
registering by hand to `register_from_model` sees its clients address
`IED1LD0/LLN0$RP$EventsRCB01` where they addressed `…$EventsRCB`. A data set or
control block already registered under the same reference fails the call with
`ServerError::AlreadyRegistered`, and a data set member that does not resolve,
or a report, GOOSE or log control block naming a data set that neither the
model declares nor the server holds, fails it with `InvalidModel`; in either
case nothing is registered. A data set
member naming a data object or a constructed attribute is registered as one
member, so no snapshot value is needed for it.

A report control block from the model has `Owner`, and a BRCB `ResvTms`,
only when the SCL file declares them (see
[Report settings and trigger options](#report-settings-and-trigger-options)).
A GOOSE control block publishes to the address of the SCL `<GSE>` the model
holds for it, with its `MinTime` and `MaxTime`: T1 is `MinTime`, Tmax is
`MaxTime`, and T2 to T4 double from T1 up to Tmax. Without a `<GSE>` it
gets APPID 0, `01-0C-CD-01-00-00` and the 4 and 1000 ms of
`RetransIntervals::default()`. `FromModelOptions::goose_comm`, when set,
chooses every destination instead. The intervals can still be changed on the
publisher:

```rust
let mut intervals = RetransIntervals::default();
intervals.t1 = Duration::from_millis(2);
intervals.tmax = Duration::from_millis(5_000);
if let Some(handle) = server.gocb_registry().find("IED1LD0", "LLN0", "gcb01") {
    handle.publisher.lock().unwrap().set_retrans_intervals(intervals);
}
```

When the model holds a connected access point of the IED, the SCL is a system
configuration, in which a GOOSE control block without `<GSE>` is disabled
(IEC 61850-8-1 §25.3.2). Without `goose_comm` such a block, and one whose
`<GSE>` has no `MAC-Address` (GOOSE over UDP/IP is not supported), is
registered without a destination: `GoCBHandle::has_destination` is false,
`DstAddress` `Addr` reads as six zero octets, and a write of `GoEna = TRUE`
answers `temporarily-unavailable`, so it publishes nothing. Add the `<GSE>`
to the SCL, or give the destination in code.

Each publisher registered from the model stamps `t`, the time of the last
stNum change (IEC 61850-8-1 §18.1.2.5), at registration and on every
`increase_st_num` and `reset`, from `FromModelOptions::wall_clock` or the
system clock, with `IedServerConfig::time_quality`. A clock before the epoch
or past the 32-bit SecondSinceEpoch is sent as the epoch with ClockFailure
set. A publisher registered through `register_gocb` is left as the
application built it.

```rust
let options = FromModelOptions::new()
    .with_goose_comm(Arc::new(|_gocb_ref: &str| {
        CommParameters::new(0x0001, [0x01, 0x0c, 0xcd, 0x01, 0x00, 0x01])
    }))
    .with_wall_clock(Arc::new(|| {
        SystemTime::now().duration_since(UNIX_EPOCH).unwrap_or_default()
    }));
let summary = server.register_from_model_with(&options)?;
if let Some(handle) = server.gocb_registry().find("IED1LD0", "LLN0", "gcb01") {
    if !handle.has_destination {
        println!("gcb01 stays disabled");
    }
}
```

### Setting groups

The server keeps the values of every setting group (IEC 61850-7-2 §16).
SelectActiveSG loads the selected group into FC=SG, SelectEditSG loads it into
FC=SE, and ConfirmEditSGValues stores FC=SE into the edited group. The handler
no longer stores or switches values; `confirm_edit_sg` returns `bool`, and
`false` refuses the commit.

In 0.3:

```rust
impl SettingGroupHandler for Settings {
    fn act_sg_changed(&self, sg: u8, _: ConnectionId) -> bool {
        self.write_group_into_sg_attributes(sg);
        true
    }
    fn confirm_edit_sg(&self, sg: u8, _: ConnectionId) {
        self.store_se_attributes_as_group(sg);
    }
}
```

In 0.4:

```rust
impl SettingGroupHandler for Settings {
    fn confirm_edit_sg(&self, sg: u8, _: ConnectionId) -> bool {
        self.persist(sg) // optional; false refuses the commit
    }
}
```

Persisted values are restored at start-up through the runtime:

```rust
let rt = server.setting_groups().lookup("IED1LD0").unwrap();
if let Err(e) = rt.set_group_value(2, &op_dl_tmms_set_val_sg, MmsValue::Integer(200)) {
    eprintln!("setting group value refused: {e:?}");
}
```

On the wire: a client reading FC=SG after SelectActiveSG reads the new group's
values, and the server's change of an FC=SG member with `dchg` is reported.

### Updates, triggers and logs

An update compares the new value with the old one and raises only the trigger
options the attribute declares (IEC 61850-7-2 Table 21): a changed value
raises data-change for `dchg`, quality-change for `qchg` and data-update for
`dupd`; an unchanged value raises only data-update.

- Rewriting a value with itself sends no data-change. To report every write,
  declare `dupd` on the attribute and enable `TriggerOptions::DATA_UPDATE` on
  the control block.
- An attribute built with `TrgOps::NONE` triggers nothing; declare the options
  it should raise. The sub-attributes of a constructed attribute take its
  trigger options, so a leaf such as `mag.f` now triggers on what `mag`
  declares.

In 0.3:

```rust
// TrgOps::NONE still raised data-change on every change
DataAttribute::new("stVal", FC::St, DataAttributeType::Boolean,
    TrgOps::NONE, MmsValue::Boolean(false));
```

In 0.4:

```rust
let st_val = DataAttribute::new("stVal", FC::St, DataAttributeType::Boolean,
    TrgOps::DCHG, MmsValue::Boolean(false));
```

- A report carries only the reasons its control block's `TrgOps` enable.
- A value a client writes with SetDataValues or SetDataSetValues raises the
  triggers it declares, as an `update_*` call does.
- `IedServer::lock_data_model` defers the triggers of the updates made while
  its guard is held and raises them as one batch when it is dropped: a URCB
  without a buffer time sends one report, and a BRCB buffers one entry. Keep
  the guard short: buffer time expiry and integrity and general interrogation
  reports wait for it.
- `LogControl::log_single_value` is removed; an update of a data set member
  writes its own log entry, and a batch writes one entry per log control
  block. To seed a log with entries of your own, write to the storage:

In 0.3:

```rust
lc.log_single_value(time_ms, data_ref, value, 0x02)?;
```

In 0.4:

```rust
let id = storage.add_entry(time_ms)?;
storage.add_entry_data(id, data_ref, value, 0x02)?;
```

- A log control block follows its configured `LogEna`: one with a data set and
  storage starts enabled unless its definition clears the flag. A
  `set_log_ena(true)` after binding the storage stays harmless.

```rust
let block = LogControlBlock::new("lcb01")
    .with_dataset("LLN0$ds1")
    .with_default_enabled(false);
```

- A log control block with integrity in `TrgOps` and `IntgPd` above zero
  writes an entry holding the whole data set every period. An application that
  wrote integrity entries itself stops, or each period is logged twice.
- `ReportingEngine::flush_after_unlock` and `InclusionFlag::NOT_UPDATED` are
  removed; dropping the data model guard delivers the batch.
- Triggers are raised in the order the values were stored, one batch at a
  time, and an `update_*` call returns once its own triggers have been
  raised, so it may wait for an update another thread made just before. A
  `LogStorage` may call `update_*` on the thread the server calls it on; that
  update is raised after the current batch and the call returns at once. It
  must not wait for an update made on another thread, for instance by
  spawning a thread that updates the server and joining it: that update waits
  for the storage to return. A `ReportSink` or `ReportBufferBackend` must not
  update the server at all.
- A `LogStorage` must not call `IedServer::lock_data_model` from its write
  methods: the server writes integrity entries while the periodic triggers
  hold that lock off, so a 0.3 storage that locked the data model there hangs
  at the first integrity entry.
- A value a client Write stores and another update replaces before the Write
  request ends is not reported or logged; the last report and log entry of
  the attribute carry the value it holds.

### Read and write handlers

A read handler decides every read that covers its node: a read of the node, of
any node above it up to the logical node or a functional-constraint group, and
of any node below it, including data set members and reads with an alternate
access. `ctx.path` is the path the handler is registered against and
`ctx.requested` the path the client named. A handler meant to guard only its
own path steps aside when they differ:

```rust
impl ReadHandler for Guard {
    fn read(&self, ctx: &ReadContext<'_>) -> ReadOutcome {
        if ctx.requested != ctx.path {
            return ReadOutcome::CacheMiss;
        }
        ReadOutcome::CacheMiss
    }
}
```

A `CacheHit` from a handler on a data object or a constructed attribute must be
a structure in model order, one member per node beneath it; another shape
answers `type-inconsistent`.

A read handler runs while the server holds none of its locks, so it may call
the server, `update_*` and `lock_data_model` included; in 0.3 such a call
could deadlock against a general interrogation or integrity snapshot. Each
handler is still asked once per read. A read that consults handlers walks its
node twice: once outside the value lock to ask the handlers, and once under
it to take the values, answering each consultation with what the handler
decided.

A write handler on a data object or sub-data-object sees every write beneath
it, with the merged value of the whole object; `ctx.requested` names the node
written. Return `HandlerWriteOutcome::Accept` for writes it does not care
about.

Read and write handlers, the control check and selection change handlers,
setting group handlers, log storages and report buffer backends run on the
blocking thread pool of the runtime when a client request, a periodic
trigger, the select timeout, the end of a command or the release of an
association reaches them, so a blocking handler holds up only its own
request. A handler is called on a different thread from one call to the
next; keep no state in thread-locals. The futures of
`WaitForExecutionHandler` and `ControlHandler` are still polled on the
runtime: move blocking work in them to `tokio::task::spawn_blocking`. A log
storage or report buffer backend that blocks also holds up the later
updates queued behind its batch, so when one can block, call `update_*` from
async code through `tokio::task::spawn_blocking`. Stop the server with
`ServerHandle::stop` before shutting its runtime down.

Handler contexts are non-exhaustive; a test builds them with the constructors:

```rust
let ctx = ReadContext::new("LD0/GGIO1$ST$Ind1", FC::St, 1).with_requested("LD0/GGIO1$ST$Ind1$stVal");
```

### Data set members

A data set member may name a data object, a sub-data-object or a constructed
attribute (IEC 61850-7-2 §13.2.2.3). `DatasetEntry` therefore holds the node
its member names instead of a single value lock, and the `value` field is
removed.

In 0.3:

```rust
let v = entry.value.read().unwrap().clone();
let lock = Arc::clone(&entry.value);
```

In 0.4:

```rust
let v = entry.read_value().expect("value lock");
let lock = Arc::clone(&entry.leaves()[0].value); // a basic-type member
```

A member an SCL file declares, FCD or FCDA, resolves against the model:

```rust
let entry = DatasetEntry::from_data_set_entry(&model, ld, &scl_entry)?;
```

A client sees such members accepted by CreateDataSet, and their values in
reads, reports and log entries as structures. A member naming an array
element is listed by GetDataSetDirectory as the variable naming the array with
an alternate access of the index and its components, written by
SetDataSetValues as that element, and read through the read handlers of the
array.

### Arrays

An SCL `count` builds an array (IEC 61850-6 §9.5.3 Table 44, §9.5.4.1), served
as an MMS array (IEC 61850-8-1 §8.1.2.7). The elements of an array data object
are its children, one per element, instead of one template element:

```rust
let element = do_node.element(0).expect("an array has at least one element");
```

Each element is a `DataAttribute`: update one with the typed `update_*`
methods on `element(i)`, the whole array with `IedServer::update_array`, which
raises the triggers of all elements as one batch, or set it without triggers
through `DataAttribute::assign`.

```rust
server.update_array(&har, MmsValue::Array(values))?;
```

A Write of a single element is served instead of answering
`object-access-unsupported`; the write handlers on the array and above it
decide it, with the array value in which the element is replaced.

### Report control block API

`handle_set_brcb_field` takes the connection the write arrived on, like
`handle_set_rcb_field`, and `handle_set_brcb_field_for_connection` is removed.

In 0.3:

```rust
handle_set_brcb_field_for_connection(&engine, path, field, value, conn_id);
handle_set_brcb_field(&engine, path, field, value);
```

In 0.4:

```rust
let outcome = handle_set_brcb_field(&engine, path, field, value, conn_id);
```

`RcbField` has `PurgeBuf`, `TimeOfEntry` and `ResvTms` variants, which
`RcbField::from_name` returns instead of `Unknown`:

```rust
match field {
    RcbField::PurgeBuf => {}
    _ => {}
}
```

`ConfigChangeResult::Applied`, which no write produced, is removed.
`BufferedReportControl::set_config_field` and `handle_purge_buf_write` return
`BrcbWriteError` instead of `ServerError`:

In 0.3:

```rust
match result {
    Err(ServerError::InvalidModel(msg)) if msg.contains("RptEna=true") => busy(),
    _ => {}
}
```

In 0.4:

```rust
match result {
    Err(BrcbWriteError::ReportingEnabled) => busy(),
    Err(BrcbWriteError::Server(e)) => fail(e),
    _ => {}
}
```

`ReportingEngine::new` and `new_with_channel_sink` take the data set registry
that DatSet writes resolve against, and `set_dataset_registry` is removed;
`IedServer` is unaffected.

In 0.3:

```rust
let mut e = ReportingEngine::new(sink);
e.set_dataset_registry(r);
```

In 0.4:

```rust
let e = ReportingEngine::new(sink, r);
```

Pass `DatasetRegistry::default()` where no DatSet write needs to resolve.
`flush_brcb_pending` and `flush_all_brcb_pending` no longer take the time
argument they did not use:

```rust
engine.flush_brcb_pending(&brcb, conn_id);
engine.flush_all_brcb_pending();
```

`ReportEncodeParams` and `BrcbReportEncodeParams` are non-exhaustive and are
built with `new`, whose last argument is the maximum PDU size of the
association:

```rust
let params = ReportEncodeParams::new(rpt_id, dat_set, &ds, &pending, max_pdu_size);
```

`BACKPRESSURE_CLOSE_THRESHOLD` is removed: a full report channel drops URCB
reports and holds BRCB entries without releasing the control block. A member
too large for the negotiated PDU size is `ReportEncodeError::MemberTooLarge`
instead of `PduTooSmall`. A custom `ReportBufferBackend` can implement
`mark_formatted` and `set_formatted_through` so that it sets BufOvfl only when
it loses an entry not yet sent.

The SQLite report buffer (`sqlite-backend`) stores each entry's value snapshot
and marks its database with schema version 1. A database created by 0.3 is
upgraded in place when it is opened; the entries it already holds have no
snapshot and are still reported with the values current at transmission.

`reporting::RESV_TMS_IMPLICIT_VALUE_S` is removed and has no replacement: no
write path applied it, and IEC 61850-7-2 defines no implicit BRCB reservation
on a write (§17.2.2.17, Table 37). Delete the code that read it. A BRCB with
`ResvTms` = 0 is held by the client that enables it only while it is enabled
and its association lasts; a client that wants it kept across a lost
association writes a positive `ResvTms` before enabling it:

```rust
rcb.set_resv_tms(30);
conn.set_rcb_values(&rcb, RcbWriteMask::RESV_TMS, false).await?;
```

Nothing changes on the wire.

### GOOSE control blocks

Every GoCB value is read from its `GoosePublisher`, so `GoCBHandle` holds the
names and the publisher only.

In 0.3:

```rust
GoCBHandle::new("LD0", "LLN0", "gcb01", publisher, 7, "LD0/LLN0$ds1", Some(id), false, comm, Some(4), Some(1000))
```

In 0.4:

```rust
let mut p = GoosePublisher::new(comm, "LD0/LLN0$GO$gcb01", Some(id), "LD0/LLN0$ds1", 7)?;
p.set_retrans_intervals(intervals); // MinTime = t1, MaxTime = tmax
let handle = GoCBHandle::new("LD0", "LLN0", "gcb01", Arc::new(Mutex::new(p)));
```

The `min_time` and `max_time` arguments become the `t1` and `tmax` of the
publisher's `RetransIntervals`, which is non-exhaustive: start from
`RetransIntervals::default()`, assign the fields, and pass it to
`set_retrans_intervals`.

| 0.3 | 0.4 |
|---|---|
| `handle.go_id_snapshot()` | `handle.publisher.lock().unwrap().go_id()` |
| `handle.conf_rev` | `….conf_rev()` |
| `handle.data_set_ref` | `….data_set_ref()` |
| `handle.nds_com` | `….needs_commission()` |
| `handle.dst_address` | `….comm_parameters()` |
| `apply_gocb_write(&h, da, &v)` | `apply_gocb_write(&registry, &h, da, &v)` |
| `registry.list_mms_names_in_domain(d)` | `registry.item_bases_in_domain(d)`, or GetNameList for every flattened name |

`encode_gocb_structure` and `encode_gocb_da` return
`Result<MmsData, DataAccessError>`. A registry built by hand checks that a
`DatSet` write names a data set the server holds only after
`with_data_set_lookup`. `IedServerConfig::edition` now takes effect: under
`Edition::Ed2_1`, `GoID` and `DatSet` are read-only, which is the only
behavior that depends on the edition.

### Associations

The server releases an association the way ACSE defines and refuses one with a
Session REFUSE carrying a CPR; see [Upgrade order](#upgrade-order). On a server
with TLS, a connection whose handshake or association setup does not complete
within `association_setup_timeout_ms` raises `AlmHandshakeTimeout` on the TLS
event handler.

`IedServer::abort_connection` returns `bool`, `true` when it found an open
association with the id and marked it for abort. In 0.3 it returned
`Result<bool>`, `Ok(false)` either way.

In 0.3:

```rust
server.abort_connection(id)?;
```

In 0.4:

```rust
if !server.abort_connection(id) {
    println!("association {id} is already gone");
}
```

### Gating associations

An `AssociationAuthenticator`, installed with `IedServerBuilder::authenticator`
or at run time with `IedServer::set_authenticator`, decides on every
association request. It receives the peer address, the called and calling
AP-title and AE-qualifier and the ACSE credentials in an `AssociationRequest`,
and returns `AssociationDecision::Accept` or `AssociationDecision::Reject` with
an acse-service-user diagnostic. A closure can be installed directly. Without
one every association is accepted, as in 0.3.

```rust
let server = IedServer::builder()
    .model(model)
    .bind(addr)
    .authenticator(Arc::new(|req: &AssociationRequest<'_>| match req.password() {
        Some(b"secret") => AssociationDecision::Accept,
        _ => AssociationDecision::Reject(AcseServiceUserDiagnostic::AuthenticationFailure),
    }))
    .build()?;
```

A refused association is answered with a Session REFUSE carrying a CPR whose
AARE has result rejected-permanent and the diagnostic the authenticator names,
and carries an Initiate-ErrorPDU with errorClass access and errorCode
object-access-denied as its user information (IEC 61850-8-1 §8.1.3.4.2.1);
then the connection closes. A 0.4 client reports it as
`ClientError::AuthenticationRejected` when the diagnostic names the calling
identity or the authentication. Only the mechanism and the decision are
logged, never a password.

### Write access policies

`IedServer::set_write_access_policy` applies to the next Write of every
association, also while the server runs: the server and the dispatcher the
builder makes share one `SharedWriteAccessPolicies`. Code that set every
policy before `start` keeps working; a policy changed later now takes effect
at once. `MmsModelDispatcher::write_policies` is a `SharedWriteAccessPolicies`,
and `MmsModelDispatcher::new` and `with_identification` take any
`Into<SharedWriteAccessPolicies>`, so a constructor given
`Arc::new(policies)` compiles unchanged.

In 0.3:

```rust
let policies: WriteAccessPolicies = *dispatcher.write_policies;
```

In 0.4:

```rust
let policies: WriteAccessPolicies = dispatcher.write_policies.get();
server.set_write_access_policy(FC::Sp, false)?; // the next Write is refused
let own = MmsModelDispatcher::new(model, mms_model, server.write_access_policies());
```

A dispatcher supplied through `IedServerBuilder::dispatcher` follows
`set_write_access_policy` when it is built from
`server.write_access_policies()`; otherwise it keeps its own policy.

### Server TimeQuality

`IedServerConfig::time_quality` is the `TimeQuality` of
`iec61850_model::utc_time`, which the server crate re-exports with
`TimeAccuracy` as `iec61850_server::TimeQuality`;
`iec61850_server::config::TimeQuality` is removed. Its accuracy is a
`TimeAccuracy`, which cannot hold the codes 25 to 30 that IEC 61850-8-1
Table 36 defines as invalid. The default is unchanged, and so is the octet
sent for every valid setting. The server stamps the `LActTm` of a setting
group control block and the GOOSE `t` of the publishers it registers from the
model with it.

In 0.3:

```rust
config.time_quality = TimeQuality { leap_seconds_known: true, clock_failure: false,
    clock_not_synchronized: false, time_accuracy: 10 };
let default = TimeQuality::default();
let bits: u8 = config.time_quality.time_accuracy;
```

In 0.4:

```rust
let default = IedServerConfig::default().time_quality;
config.time_quality = TimeQuality::new(true, false, false, TimeAccuracy::bits(10)?);
let bits: Option<u8> = config.time_quality.time_accuracy.significant_bits();
let TimeQuality { clock_failure, .. } = config.time_quality;
```

`significant_bits()` is `None` for an unspecified accuracy, and `code()` gives
the five bits as sent. The type is non-exhaustive, so a pattern on it ends
with `..`.

## SCL and scl-build

### Same version, regenerated models

The code generation support of `iec61850-scl` is a single hidden module, and
`build_model`, `__rt` and `__build_internals` are gone, so
`iec61850-scl-build` and `iec61850-scl` must be the same version and a
`model.rs` generated by an older `iec61850-scl-build` must be regenerated.
Code that used `iec61850_scl::build_model::b_type_to_dat`, `parse_fc` or the
other helpers works with the model types instead.

A model the run-time build rejects is reported as `CompileError::BuildModel`,
located at the offending element; `CompileError::ResolveScl` covers stage 2
only:

```rust
match iec61850_scl_build::compile_icd("model.icd").compile() {
    Err(CompileError::ResolveScl(e)) => panic!("{e}"),
    Err(CompileError::BuildModel { ied, source, .. }) => panic!("{ied}: {source}"),
    _ => {}
}
```

`tokens::emit_default_mms_value` is removed:

```rust
let tokens = tokens::emit_mms_value(&MmsValue::default_for(dat));
```

### Lookups by functional constraint

`IedModel::node_by_object_ref` honors the functional constraint the `ObjectRef`
carries, and `node_by_object_ref_fc` is removed. `DataObject::child_by_name`
takes the constraint, and `child_by_name_fc` is removed.

In 0.3:

```rust
model.node_by_object_ref_fc(&r, FC::Se);
dobj.child_by_name("stVal");
dobj.child_by_name_fc("setVal", fc);
```

In 0.4:

```rust
let mut r = r.clone();
r.fc = Some(FC::Se);
let node = model.node_by_object_ref(&r);
let st_val = dobj.child_by_name("stVal", None);
let set_val = dobj.child_by_name("setVal", Some(fc));
```

### One name per data set path segment

A `DataSetEntry::do_path` segment holds one name; a segment containing `.` is
rejected by `IedModelBuilder::build` with `DataSetEntryUnresolved`.

In 0.3:

```rust
DataSetEntry::new("MMXU1", FC::Mx, vec!["TotW".into(), "mag.f".into()]);
```

In 0.4:

```rust
let entry = DataSetEntry::new("MMXU1", FC::Mx, vec!["TotW".into(), "mag".into(), "f".into()]);
```

### Raw elements

`RawDoType::das` and `RawDoType::sdos` are replaced by `children`, which keeps
the declared order, and the `das()` and `sdos()` iterators. `RawDaDef::count`
is an `Option<RawCount>`, and `RawBda` and `RawSdoDef` carry one.

In 0.3:

```rust
for da in &dot.das {}
for sdo in &dot.sdos {}
```

In 0.4:

```rust
for da in dot.das() {}
for sdo in dot.sdos() {}
let n = raw_da.count.as_ref().and_then(RawCount::elements); // None for a scalar
```

### Report settings and trigger options

A report control block built from SCL, at run time or by
`iec61850-scl-build`, has the optional `Owner` attribute only when the
`<ReportSettings>` of the access point's `<Services>`, or else of the IED's,
says `owner="true"`, and a BRCB has `ResvTms` only when it says
`resvTms="true"`; IEC 61850-6 defaults both to false. A server that should
keep serving both declares them:

```xml
<IED name="IED1">
  <Services>
    <ReportSettings owner="true" resvTms="true"/>
  </Services>
  …
</IED>
```

A peer of a server whose file declares neither no longer sees `Owner` or
`ResvTms` on its control blocks, and reserves a BRCB by enabling it. Control
blocks registered in code keep them; `Rcb::new(..).with_owner(false)`,
`Brcb::new(..).with_owner(false)` or `Brcb::new(..).with_resv_tms(false)`
removes one. The model carries the setting as
`ReportControlBlock::has_owner` and `has_resv_tms`.

A `<TrgOps>` that leaves out `gi` now enables general interrogation, as
IEC 61850-6 §9.3.8 defaults it to true, so a peer reads GI in `TrgOps` and a
`GI = TRUE` write produces a general interrogation report. A log control block
is unchanged. To keep the old behavior, say so:

```xml
<TrgOps dchg="true" gi="false"/>
```

Projects using `iec61850-scl-build` pick up both changes when the build script
regenerates the model. The output of `summarize::summarize_model` changes as
well: the report control block line gains `indexed=`, `max=`, `trg=`,
`optFlds=`, `bufTm=`, `intgPd=`, `owner=` and `resvTms=`, the log control
block and data attribute lines gain fields, and data objects and their
children follow the declared order instead of sorted names, so saved
summaries must be regenerated.

### Communication section

The `<Communication>` section is read and checked instead of skipped with a
warning (IEC 61850-6 §9.4): subnetworks, connected access points with their
server addresses, and the `<GSE>` and `<SMV>` addressing of the control
blocks. A file that used to load may now be refused:

- An empty `<Address>`, or a structure the SCL schema does not allow, now
  fails to parse, and a model built for an IED whose own `<ConnectedAP>`
  names an access point it lacks, whose `<GSE>` or `<SMV>` names a control
  block that does not exist, or whose `MinTime` is above its `MaxTime`, now
  fails to build; each is refused with an `SclParseError` at the element. A
  `<ConnectedAP>` naming an IED the file does not declare, and such a
  reference of another IED, are skipped with a warning, so such files load as
  before.
- Address values in another form than the schema's (IEC 61850-8-1 §25.3.1
  Table 162, §25.3.2 Table 163, §25.3.3 Table 164, IEC 61850-9-2 Clause 11
  Table 19), such as a lower-case MAC address `01-0c-cd-01-00-01` or a
  VLAN-ID of `1`, load as before and are logged as warnings; a value that
  cannot be read, such as a MAC address of five octets, also loads, and a
  GOOSE control block that takes its destination from it is registered
  disabled. A short value is read as hexadecimal, as the schema form is: a
  VLAN-ID of `10` is 0x010 and an APPID of `10` is 0x0010, not decimal ten.
  An OSI selector written as an odd run of digits takes one leading zero,
  `1` being the octet 01 and `001` the octets 00 01; it is not padded to any
  fixed length. White space around a value, a line break or a tab included,
  is read past. Each such value is logged with the value it is read as,
  written in the schema form.

Correct the file where it is refused; the error names the line, the
element path and the expected form. There is no option to skip the section.
A fractional `MinTime` or `MaxTime`, valid as an `xs:decimal`, is rounded to
the nearest whole millisecond with a warning; `<PhysConn>` is not read.

Code that read addresses from the XML itself reads them from the model, and
can turn them into publication settings:

```rust
let ip = model.connected_ap("AP1").next().and_then(|ap| ap.address.as_ref()).and_then(|a| a.ip());
let gse = model.gse_address("LD0", "gcb1");
let comm = gse.map(|g| CommParameters::from_address(&g.address)).transpose()?;
let intervals = gse.map(RetransIntervals::from_gse);
let sv = match model.smv_address("LD0", "svcb1") {
    Some(address) => SvPublisherBuilder::new(src_mac).with_address(address)?,
    None => SvPublisherBuilder::new(src_mac),
};
```

`IedServer::register_from_model` publishes each GoCB to the address of its
`<GSE>`; see [Registering what the model declares](#registering-what-the-model-declares).
Neither the server nor anything else binds the server address the model
holds; the application chooses where to listen. `iec61850-scl-build` puts
the same addressing into the generated model. `summarize::summarize_model`
prints a `ConnectedAP` line per connected access point and a `GSE address=` or
`SMV address=` line below each addressed control block; a stored summary of a
model built from a file with a Communication section has to be regenerated.

### Control block data set references

Stage 2 checks the `datSet` of every `<ReportControl>`, `<LogControl>`,
`<GSEControl>` and `<SampledValueControl>` against the `<DataSet>` elements of
its own logical node, as the keys of the SCL schema require (IEC 61850-6
Annex A). A `datSet` naming a data set the logical node does not declare fails
`resolve` with `ErrorKind::UnresolvedDataSetReference`, located at the control
block and its `datSet` attribute; an absent or empty `datSet` is accepted as
before. A file that resolved with such a reference, and built a control block
naming nothing, is now refused: declare the data set in the logical node of
the control block, or leave `datSet` out of a report or log control block a
client configures at run time.

```rust
match iec61850_scl::parse_scl(xml).and_then(|raw| raw.resolve()) {
    Err(e) => match e.kind.as_ref() {
        ErrorKind::UnresolvedDataSetReference { data_set, .. } => {
            println!("{}: no data set {data_set}", e.element_path)
        }
        _ => {}
    },
    Ok(_) => {}
}
```

### Model changes a peer sees

- The members of a data object follow the order its DOType declares them in
  (IEC 61850-6 §9.5.3, IEC 61850-8-1 §7.3.1). The SCL path used to put every
  attribute before every sub-object, so a SEQ, WYE or DEL changes its
  structure on the wire.
- A `count` builds an array, so the MMS type of such an attribute changes from
  the element type to an array of it. A `count` naming no attribute of an
  integer bType in the same type definition is rejected; when the type gives
  the named attribute no `<Val>`, the count is the value an instance gives it,
  and without one the declaration is built as a scalar with a warning.
- The sub-attributes of a constructed attribute take its trigger options, so a
  leaf such as `mag.f` triggers reports and log entries.
- An empty `smvID` takes the control block reference.

### Other changes

- `DataAttributeType` has `Int24`, `SvOptFlds` and `LogOptFlds`; a `match` on
  it needs them or a wildcard arm.
- A raw `<LogControl>` defaults `reasonCode` to true.
- `<RptEnabled max>` is read from the child element; the attribute
  `rptEnabledMax` is no longer read.
- `SclParseError` displays as "SCL error at …" instead of "SCL parse error at
  …"; code that matched the text matches the new prefix.
- New rejections: `<RptEnabled max="0">`, more than 99 indexed report
  instances, a `sGroup` of 0, above 255 or above `numOfSGs`, two values for one
  setting group, a `numOfSGs` above 255, a `<Header>` without `id`, outside
  `<SCL>` or repeated, a file that expands to more than
  `ResolveOptions::max_expanded_nodes` model nodes, the FC=SG views derived
  from FC=SE attributes included, and the Communication section and data set
  reference errors above.

## GOOSE and Sampled Values

### 802.1Q tag by default

GOOSE and Sampled Values frames carry an 802.1Q tag by default, priority 4 and
VID 0, as IEC 61850-8-1 Annex C.2.2 and IEC 61850-9-2 Tables 6 and 7 require.
Peers see `81 00 80 00` after the source address; receivers must accept tagged
frames, so no peer needs upgrading. To keep untagged frames:

```rust
let comm = CommParameters::new(app_id, dst_mac).without_vlan();
let sv = SvPublisherBuilder::new(src_mac).without_vlan();
```

A server GoCB's `DstAddress` reads priority 4 instead of 0 for parameters that
never set one. Code that read the savPdu of its own frame at
`SV_HEADER_NO_VLAN` reads it at `SV_HEADER_WITH_VLAN`.

### Subscriber filters

A GOOSE subscriber applies its APPID and destination MAC filters whether or not
a gocbRef filter is set, and `observer()` means "any gocbRef". A subscriber
that set `app_id(..)` or `dst_mac(..)` without a gocbRef and relied on
receiving everything drops those calls, or is built as an observer:

```rust
let everything = GooseSubscriber::new_observer();
let one_appid = GooseSubscriberBuilder::default().app_id(0x0001).observer().build();
```

`.gocb_ref(r).observer()` now means any gocbRef; drop `.observer()` to filter
on `r`.

### Subscriber events

`GooseEvent` and each of its variants are non-exhaustive: a pattern on a
variant ends with `..`, and a `match` on the event needs a wildcard arm.

In 0.3:

```rust
match ev {
    GooseEvent::NewState { prev_st_num, state, parse_result } => {}
    GooseEvent::Retransmission { state, parse_result } => {}
    GooseEvent::Expired { last_state } => {}
}
```

In 0.4:

```rust
match ev {
    GooseEvent::NewState { state, .. } => println!("stNum {}", state.st_num),
    GooseEvent::Retransmission { .. } => {}
    GooseEvent::Expired { last_state, .. } => println!("expired after stNum {}", last_state.st_num),
    _ => {}
}
```

### PDU and frame types

- `GoosePdu::go_id` is a `String`; `GoosePdu::new` sets it to the gocbRef.
  `pdu.go_id = None` becomes `pdu.go_id = pdu.gocb_ref.clone()`, and
  `decoded.go_id.unwrap()` becomes `decoded.go_id`. The wire format is
  unchanged.
- `SmpMod` carries the full INT16U of IEC 61850-9-2 Table 14:
  `SmpMod::from_byte(b)` becomes `SmpMod::from_u16(b.into())`,
  `m.to_byte()` becomes `m.to_u16()`, `Unknown` holds a `u16`, and
  `SvPublisherBuilder::set_smp_mod(h, mode)` takes the mode as a `u16`
  instead of a `u8`.
- `SvError::Other(String)` is replaced by `SvError::Platform(EthernetError)`;
  an `EthernetSink` that returned `Err(SvError::Other(e.to_string()))` returns
  `Err(e.into())` or uses `?`.
- `GooseFrame` and `SvFrame` are non-exhaustive; build them with
  `GooseFrame::new(header, pdu_bytes)` and `SvFrame::new(header, pdu_bytes)`.

```rust
let mode = SmpMod::from_u16(u16::from(raw_mode));
let raw = mode.to_u16();
```

### Timestamps as UtcTime

The GOOSE `t` and the Sampled Values `refrTm` are a `UtcTime` instead of eight
raw bytes. `UtcTime`, `TimeQuality`, `TimeAccuracy` and `UtcTimeError` live in
`iec61850_model::utc_time`; `iec61850-goose` re-exports them at its root, and
`iec61850-sv` at its root and as `iec61850_sv::utc_time`. A `UtcTime` is
always a valid encoding (IEC 61850-8-1 §8.1.3.7).

| 0.3 | 0.4 |
|---|---|
| `SvPublisher::set_refr_tm(h, [u8; 8])` | `set_refr_tm(h, UtcTime)` |
| `Asdu::refr_tm: Option<[u8; 8]>` | `Option<UtcTime>` |
| `SvSubscriberAsdu::refr_tm: Option<&[u8; 8]>` | `Option<UtcTime>` |
| `GoosePublisher::set_timestamp([u8; 8])` | `set_timestamp(UtcTime)` |
| `GoosePdu::t: [u8; 8]` | `UtcTime`; `GoosePdu::new` starts it at `UtcTime::NULL`, the same eight zero octets |
| `GooseSubscriberState::timestamp_raw` | `timestamp`, a `UtcTime` |

The functions below return `Box<dyn std::error::Error>`, because
`UtcTimeError` and the crate errors are separate types:

```rust
let since_epoch = SystemTime::now().duration_since(UNIX_EPOCH)?;
let tq = TimeQuality::new(true, false, false, TimeAccuracy::bits(20)?);
publisher.set_refr_tm(h, UtcTime::from_duration_since_epoch(since_epoch, tq)?)?;
// or, from bytes already encoded:
publisher.set_refr_tm(h, UtcTime::from_bytes(bytes)?)?;
if let Some(t) = listener_asdu.refr_tm {
    if !t.time_quality().clock_failure {
        let _since_epoch = t.duration_since_epoch();
    }
    let _bytes: [u8; 8] = t.to_bytes();
}
asdu.refr_tm = Some(UtcTime::from_bytes(bytes)?);
```

```rust
let tq = TimeQuality::new(true, false, false, TimeAccuracy::bits(20)?);
publisher.set_timestamp(UtcTime::from_duration_since_epoch(since_epoch, tq)?);
let t: UtcTime = state.timestamp;
let raw: [u8; 8] = t.to_bytes();
pdu.t = UtcTime::from_bytes(bytes)?;
```

A GOOSE publisher can read `t` from a clock on every stNum change instead of
being set by hand: `set_timestamp_source` installs a `TimestampSource` that
`increase_st_num` and `reset` call. Without one, `t` keeps the value
`set_timestamp` gave it, as before.

```rust
let source: TimestampSource = Box::new(move || {
    let now = SystemTime::now().duration_since(UNIX_EPOCH).unwrap_or_default();
    UtcTime::from_duration_since_epoch(now, tq).unwrap_or(UtcTime::NULL)
});
publisher.set_timestamp_source(Some(source));
```

On the wire: a received frame whose `t` or `refrTm` carries a TimeAccuracy
of 25 to 30, which IEC 61850-8-1 Table 36 defines as invalid, is dropped like
any other malformed frame (`GooseError::InvalidTimestampQuality`,
`SvError::InvalidRefrTm`); every other value is delivered as before, its
distance from the local clock and its quality flags left to the listener.
Publishers of this crate cannot produce such a value, so no simultaneous
upgrade is needed.

### Removed items

- `GooseReceiver::set_interface_id` and `interface_id`, which `start_thread`
  never read. Choose the interface when opening the source, for example with
  `iec61850_hal::ethernet::open_socket(&EthernetConfig::new("eth0"))`, then
  pass it to `start_thread`.
- The `tokio-runtime` feature of `iec61850-sv`, which enabled no code; drop it
  from the dependency's features. The feature of the same name in
  `iec61850-goose` stays.

### Simulation

The S bit of the GOOSE Reserved1 field mirrors the Simulation parameter
(IEC 61850-8-1 Annex C.2.5), and Sampled Values carry the Simulate bit
(IEC 61850-9-2 §5.3.3.4.4). Both are new; nothing changes for an application
that does not set them.

A GOOSE subscriber keeps the sequence state, the confRev check and the
timeAllowedToLive supervision of the simulated and of the original messages
of one gocbRef apart. With `SimulationFilter::Any`, the default, the first
simulated message raises `NewState` with `prev_st_num` 0, each of the two
expires on its own, and an observer counts them as two publications against
`max_streams`. `GooseSubscriberState::is_simulated` tells them apart: it is
true when the PDU `simulation` member or the S bit of Reserved1 is set.

```rust
match ev {
    GooseEvent::NewState { state, prev_st_num, .. } if state.is_simulated() => {
        println!("simulated stNum {} after {prev_st_num}", state.st_num)
    }
    GooseEvent::NewState { state, .. } => println!("stNum {}", state.st_num),
    _ => {}
}
```

## TLS

### Removed settings

`TlsConfigBuilder::chain_validation` and `renegotiation_interval` only logged a
warning: chain validation always runs and no renegotiation is initiated. Drop
the calls.

### The stream type

`TlsAcceptor::accept` and `TlsConnector::connect` return
`iec61850_tls::TlsStream` instead of the stream types of tokio-rustls.

In 0.3:

```rust
let stream: tokio_rustls::server::TlsStream<TcpStream> = acceptor.accept(tcp).await?;
let certs = stream.get_ref().1.peer_certificates();
```

In 0.4:

```rust
let stream: iec61850_tls::TlsStream<TcpStream> = acceptor.accept(tcp).await?;
let certs = stream.peer_certificates();
let version = stream.protocol_version();
let suite = stream.negotiated_cipher_suite();
let resumed = stream.is_resumed();
```

`protocol_version` returns an `Option<TlsVersion>` of this crate and
`negotiated_cipher_suite` an `Option<rustls::CipherSuite>`; `is_resumed`
replaces a check of the rustls `handshake_kind()`. `get_ref` returns the
underlying transport. The SNI name and ALPN have no accessor.

TLS 1.3 session tickets stay off by default, as since 0.3.3;
`TlsConfigBuilder::tls13_session_tickets(n)` enables them on a server.

### Handshake errors

A failed handshake is classified by its cause instead of always being
`TlsError::Io`:

```rust
match err {
    TlsError::Verification(e) => println!("certificate: {e}"),
    TlsError::VersionUnsupported(e) | TlsError::CipherUnsupported(e) => println!("no common parameters: {e}"),
    TlsError::Handshake(e) => println!("handshake: {e}"), // e.g. an alert from the peer
    TlsError::Io(e) => println!("transport: {e}"),
    _ => {}
}
```

On the client side a TLS error before the association is established,
including an alert received after the handshake, is `ClientError::TlsHandshake`
(see [TLS handshake failures and the connect deadline](#tls-handshake-failures-and-the-connect-deadline)),
and an alert on an established association reaches `ClientError::Transport`
with its text. Nothing changes on the wire, except that a refused client of
either version now receives the server's alert instead of a reset.

## SNTP

`SntpServerConfig::poll` is removed, since a reply copies the poll field of its
request, and the configuration is no longer `Copy`: clone it instead. The new
`clock` field reports the synchronization state of the served clock.

In 0.3:

```rust
let mut config = SntpServerConfig::default();
config.poll = 6;
let copy = config;
```

In 0.4:

```rust
let mut config = SntpServerConfig::default();
let clock = SntpClock::new(SntpClockStatus::unsynchronized(None));
config.clock = clock.clone();
let copy = config.clone();
// later
clock.set(SntpClockStatus::synchronized(Some(ts)));
```

`SntpClockStatus::synchronized` and `unsynchronized` build the status; its
variants are non-exhaustive and cannot be built with a struct expression. The
default is a synchronized clock under continuous discipline, which replies as
0.3 did. A client sees leap indicator 3 and stratum 16 only when the
application reports an unsynchronized clock.

## MMS and transport layers

### Transport errors

`TransportError` carries the cause of a failure: `Io { kind, detail }` and
`Closed { kind }`, built with `TransportError::io`, `closed` and
`with_detail`. `Other` is removed, and the type is no longer `Copy`.

In 0.3:

```rust
.map_err(|_| TransportError::Io)
```

In 0.4:

```rust
let plain = read_result.map_err(|_| TransportError::io(IoErrorKind::Other));
// with the text of the underlying error
let detailed = write_result.map_err(|e| TransportError::io(IoErrorKind::Other).with_detail(e.to_string()));
```

A `match` names the fields it reads, `TransportError::Io { kind, .. }` or
`TransportError::Closed { .. }`. `CotpError::Io` carries the `TransportError`;
call `to_string()` where the text was used. The MMS client reports an I/O
failure of the transport as `ClientError::Transport`, so a caller that treated
`ConnectionLost` as the end of the connection also handles `Transport(_)` and
`ReleasedByPeer`.

### Outstanding requests

`MmsClientBuilder::max_outstanding` takes a `u16`, is proposed to the server in
the Initiate request, and the negotiated limit is enforced, counting requests
that timed out until their late answers arrive.

In 0.3:

```rust
MmsClientBuilder::new().max_outstanding(8u32)
```

In 0.4:

```rust
let builder = MmsClientBuilder::new().max_outstanding(8u16);
```

A confirmed call dropped by its caller, for instance on an outer timeout,
releases its invokeID: after its request was sent it counts as outstanding
until the late answer arrives, which is discarded, and a call dropped while
its request was being written closes the connection, since the request may
be on the wire only in part. Connecting while an association is established
closes it without a release first, and every new association starts with
every outstanding slot free. `MmsClient::association_id` and
`BlockingMmsClient::association_id` number the associations of a client.

A peer that releases the association with a Session FINISH now receives a
DISCONNECT carrying an RLRE before the client closes, and the release is
reported as `ClientError::ReleasedByPeer`.

### Blocking MMS client

`BlockingMmsClient::into_inner` is replaced by `into_parts`, which returns the
async client together with the runtime that owns the socket and timers of its
association. The client `into_inner` returned still reported `Connected`, but
its first request failed because that runtime had been dropped.

In 0.3:

```rust
let mut client = blocking.into_inner();
```

In 0.4:

```rust
let (mut client, rt) = blocking.into_parts();
let value = rt.block_on(client.read("LD0", "LLN0$ST$Mod$stVal"))?;
```

A connected client runs on the returned runtime: drive it with `block_on`.
Once the runtime is dropped the association can no longer be used, and like
the wrapper, the runtime must not be dropped or blocked on from within an
async runtime.

### Presentation contexts

`PresentationError::UnknownAbstractSyntax` and `InvalidTransferSyntax` are
removed: `parse_connect` records a rejection for an unsupported context
instead of failing. A caller that accepts connections itself checks the
result and refuses the connection when ACSE and MMS are not both accepted:

```rust
let r = parse_connect(&mut pres, cp)?;
if !pres.accepts_acse_and_mms() {
    let mut cpr = BytesMut::new();
    encode_cpr(&pres, Some(0), None, &mut cpr);
    let mut refuse = BytesMut::new();
    encode_refuse_with_user_data(&cpr, &mut refuse)?;
}
```

### ReadJournal requests

`JournalRange` is removed: `ReadJournalRequest` carries the four optional
fields of the request, `range_start`, `range_stop`, `list_of_variables` and
`entry_to_start_after`. `ReadJournalRequest`, `WireJournalEntry` and
`WireJournalVariable` are non-exhaustive.

In 0.3:

```rust
match req.range {
    JournalRange::TimeRange { start_ms, end_ms } => {}
    JournalRange::StartAfter { starting_time_ms, entry_id } => {}
}
```

In 0.4:

```rust
if let Some(JournalRangeStart::StartingTime(start_ms)) = req.range_start {}
if let Some(JournalRangeStop::EndingTime(end_ms)) = req.range_stop {}
if let Some(after) = &req.entry_to_start_after {
    let _ = (after.time_ms, after.entry_id);
}
let entry = WireJournalEntry::new(entry_id, occurence_time_ms, variables);
let var = WireJournalVariable::new("LD0/GGIO1$ST$Ind1$stVal", value, 0x02);
let req = ReadJournalRequest::new("LD0", "LLN0$GeneralLog")
    .with_range_start(JournalRangeStart::StartingTime(start_ms));
```

`ReadJournalRequest::time_range` and `start_after` are unchanged. A 0.4 client
sends the same bytes as 0.3 for the two ACSI queries; a 0.3 server refuses the
new combinations with an access error.

### DefineNamedVariableList entries

`DefineNamedVariableEntry` is non-exhaustive and gains `alt_access`, an
optional alternate access selecting an array element and the components
inside it (IEC 61850-8-1 §7.3.3, §7.3.4, Table 151). Build an entry with the
constructor.

In 0.3:

```rust
let entry = DefineNamedVariableEntry { domain_id: "LD0".into(), item_id: "GGIO1$ST$Ind1$stVal".into() };
```

In 0.4:

```rust
let plain = DefineNamedVariableEntry::domain("LD0", "GGIO1$ST$Ind1$stVal");
let element = DefineNamedVariableEntry::domain("LD0", "MHAI1$MX$HA$phsAHar")
    .with_alt_access(AlternateAccess::index_component(3, "cVal$mag$f")?);
```

`MAX_DEFINE_ENTRIES` and `MAX_WRITE_ITEMS` are 4096 instead of 100.

### Alternate access

`AlternateAccessSelector` is non-exhaustive and gains `Component`, which
covers component selection and the chains IEC 61850-8-1 §24.2.2.4 Table 139
uses. A `match` on it needs a wildcard arm, and
`AlternateAccess::leading_components` folds the components into a flattened
name.

### Service errors

`ServiceError` is non-exhaustive and carries the serviceSpecificInformation of
a ServiceError; build it with its constructors:

```rust
let err = ServiceError::new(class)
    .with_service_specific(ServiceSpecificInfo::DeleteNamedVariableList(n));
```

`ClientError::ServiceError` of `iec61850-mms` carries it as `service_specific`,
so a pattern on the variant ends with `..`. Code that reports an MMS client
error itself, such as a test double of a peer, builds it with the
constructors, which take the fields the error always carries and leave the
optional ones to methods: `service_error` with `with_service_specific`,
`session_refused` with `with_reason_code`, `with_transport_disconnect` and
`with_provider_reason`, and `reject`, `service_timeout`, `connect_timeout`,
`not_connected`, `pdu_too_large`, `initiate_failed`, `tls_handshake` and
`authentication_rejected`.

In 0.3:

```rust
Err(ClientError::ServiceError { error_class }) => {}
let refused = ClientError::SessionRefused { reason_code: Some(2), transport_disconnect: None, provider_reason: None };
```

In 0.4:

```rust
match err {
    ClientError::ServiceError { error_class, .. } => println!("refused: {error_class:?}"),
    _ => {}
}
let refused = ClientError::session_refused().with_reason_code(2);
let failed = ClientError::service_error(class)
    .with_service_specific(ServiceSpecificInfo::DeleteNamedVariableList(n));
let handshake = ClientError::tls_handshake(TlsFailureKind::Timeout, "handshake timed out");
```
